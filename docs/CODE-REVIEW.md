## Outstanding release gaps, in priority order

1. **Authoritative LAN service is absent.** `src/engine/roomStore.ts` uses browser memory, localStorage, and BroadcastChannel. Separate phones do not share a room; each open tab also runs its own clock. Vite binding to a LAN address only makes the page reachable. Implement P01 with one server, same-origin transport, and serialized commands before calling this a phone party game.
2. **No authentication or private projections.** The seat switcher, host tools, all player tokens, all clues, and answer keys exist in the same client bundle. These are simulator controls, not permissions. Implement server-issued seat credentials and separate TV, player, host, and author views. No secret should enter another client's payload.
3. **No durable transactional recovery or command deduplication.** Local phase guards prevent repeated effects within this prototype, but do not supply command IDs, transactional writes, persisted random outcomes before resolution, recovery backups, or secure reconnection. Reloaded timed phases are paused as a limited local safeguard. Full P04 remains unimplemented.
4. **Content is not yet data-driven.** Narrative effects, start scenes, puzzle narration, and endings depend on hardcoded scene IDs. Mission two reuses these IDs, so it inherits first-mission effects and prose. It is a demonstration asset, not proof of P05. Replace executable callbacks with validated, allowlisted data; add content import, digests, version pinning, graph checks, and content-driven endings.
5. **Timing and collective arbitration remain incomplete.** Scenes start a selection timer immediately; there is no distinct untimed reading/discussion stage, server deadline, disconnect auto-pause, or rotating player tie-break window. Conflicting puzzle candidates use a deterministic squad-count fallback, not the specified individual vote. Shield purchases and standard hints bypass the required group vote; Engineer/Guardian request conflicts still favor arrival order. The market answer/prediction steps are visible in a single phase. Implement these together with the server phase machine.
6. **Several abilities and season details remain partial.** Engineer repair discounts are described but have no consent/selection UI. Family contact unlocks, all late-delivery narration, and the exact season flag contract need further work. Avoid treating the local second pack or season record as release-complete.
7. **Actual device and group validation is outstanding.** Desktop Chrome and simulated viewports were checked; no nine-phone room, Safari device, Internet-disconnected complete session, TV viewing-distance check, or group usability/balance playtest has been performed.

## Verification

- `npm test`: 15 local automated tests, including every roster size, default Shield, family modifier, Repel/clamping order, evacuation priority, Effort priority, prediction ties, affordability, paused/late inputs, ability consumption, Guardian reactions, bounded puzzle retries, season preservation, and a complete first-mission path.
- `npm run test:ui`: desktop title/lobby/ferry, guide opening and Escape, mobile controller, 390/768/1024px layouts, no horizontal title/controller overflow, no browser page errors, no external runtime requests in the checked desktop flow. Uses installed Chrome, not actual phones.
- `npm run lint`: TypeScript check.
- `npm run build`: production bundle, including locally served font files and artwork.

Passing these checks supports the changes above; it does not establish release acceptance under section 22. The next development milestone should be P01, with the rules regression checks retained as the server is introduced.
